# Entities Created & Exposed Services

A complete reference of all entities automatically generated by **Multizone Thermostat** and services available for scripts and automations.

---

## 1. Master Plant Entities (Whole-House Supervision)

| Entity ID (Example) | Domain | State / Range | Description |
|---|---|---|---|
| `switch.master_control_heating_master` | Switch | `on` / `off` | **Master Plant Switch**: Powers ON or OFF climate control for the entire home. |
| `switch.master_control_allow_split_heating` | Switch | `on` / `off` | <span class="badge-beta">BETA</span> Global toggle to permit or lock Split AC heating. |
| `switch.master_control_allow_split_cooling` | Switch | `on` / `off` | <span class="badge-beta">BETA</span> Global toggle to permit or lock Split AC cooling. |
| `switch.master_control_anti_seize_summer_protection` | Switch | `on` / `off` | Enables summer anti-seize valve exercise. |
| `switch.master_control_anti_frost_protection` | Switch | `on` / `off` | Emergency frost protection toggle. |
| `switch.time_geofencing_geofencing` | Switch | `on` / `off` | Automated transition to Away preset on departure. |
| `switch.time_geofencing_auto_night_mode` | Switch | `on` / `off` | Automated clock-based transition to Sleep preset. |
| `select.master_control_heat_source_priority` | Select | `auto`, `hybrid`, `combined`, `electric_only`, `gas_only` | <span class="badge-beta">BETA</span> Arbitrates between gas boiler and heat pump / splits. |
| `select.master_control_master_operation_mode` | Select | `heat`, `cool` | <span class="badge-beta">BETA</span> Master seasonal switch between Heating and Cooling. |
| `select.master_control_global_preset` | Select | `manual`, `eco`, `comfort`, `sleep`, `away` | Global household temperature preset selector. |
| `select.master_control_demand_strategy` | Select | `max`, `weighted_average`, `sum_capped` | Aggregation formula for central heating plant demand. |
| `number.master_control_min_cycle_on` | Number | 1 – 30 min (default: 5) | Minimum continuous burner run time. |
| `number.master_control_min_cycle_off` | Number | 1 – 30 min (default: 5) | Minimum rest period before burner restart. |
| `number.master_control_hp_min_cycle_on` | Number | 1 – 30 min | <span class="badge-beta">BETA</span> Independent minimum continuous Heat Pump compressor run time. |
| `number.master_control_hp_min_cycle_off` | Number | 1 – 30 min | <span class="badge-beta">BETA</span> Independent minimum Heat Pump compressor rest period. |
| `number.master_control_valve_delay` | Number | 0 – 300 sec (default: 0) | Pump delay to wait for motorized valve stroke. |
| `number.master_control_anti_seize_idle_days` | Number | 1 – 60 days (default: 15) | Inactivity days before running anti-seize stroke. |
| `number.master_control_anti_seize_duration` | Number | 1 – 15 min (default: 2) | Duration of valve opening during anti-seize. |
| `number.master_control_weather_curve` | Number | 0.0 – 3.0 (default: 0.0) | Outdoor weather compensation curve multiplier. |
| `number.master_control_anti_frost_temperature` | Number | 3.0 – 12.0 °C (default: 7.0) | Emergency freeze protection threshold. |
| `number.master_control_frost_flow_temp` | Number | °C | Configurable boiler flow temperature during emergency frost protection. |
| `sensor.master_control_master_demand` | Sensor | 0.0 – 100.0% | Aggregated central plant demand (active in both `heat` and `cool`). |
| `sensor.master_control_stato_salute_impianto` | Sensor | 0 – 100% | Overall heating plant health score. |
| `sensor.master_control_frequenza_accensioni_caldaia` | Sensor | cycles/h | Boiler hourly ignition cycle frequency. |
| `sensor.master_control_ore_funzionamento_caldaia_24h` | Sensor | hours | Cumulative boiler runtime over the last 24h. |
| `binary_sensor.master_control_plant_anomaly` | Binary Sensor | `on` / `off` | Active when hydraulic or telemetry anomalies exist. |

## 2. Per-Zone Entities (Individual Rooms)

All per-zone entities are grouped under each room's dedicated Home Assistant device (`Zone <Name>`), organized into **Controls**, **Configuration**, and **Diagnostics** categories:

| Entity ID (Example for "Living Room") | Domain / Category | State / Values | Description |
|---|---|---|---|
| `climate.multizone_thermostat_living` | Climate (Control) | hvac_modes, setpoint, presets | **Primary Room Climate**: Sets target, HVAC mode, and displays room status. |
| `select.zone_modes_living_mode` | Select (Control) | `primary`, `secondary`, `bypass` | **Room Thermal Role**: Determines if room can ignite central boiler. |
| `switch.living_pid_manual_unlock` | Switch (Config) | `on` / `off` | Unlocks manual editing of seasonal PID gains (`Kp`, `Ki`, `Kd`). Defaults to locked. |
| `number.living_pid_kp` / `ki` / `kd` | Number (Config) | float | Per-zone seasonal PID gains for the active season (`heat` or `cool`). |
| `button.living_reset_autotuner` | Button (Config) | press | Resets the active season's autotuner and automatically relocks `PID Manual Unlock`. |
| `switch.zone_modes_sync_controlli_fisici_living` | Switch (Config) | `on` / `off` | Bidirectional synchronization for physical TRV dial turns. |
| `switch.zone_modes_apporto_passivo_living` | Switch (Config) | `on` / `off` | Passive heat intake mode (steals heat without requesting ignition). |
| `sensor.multizone_brain_living_fabbisogno` | Sensor (Diagnostic) | 0.0 – 100.0% | Real-time PID demand percentage. |
| `sensor.multizone_brain_living_autotuning` | Sensor (Diagnostic) | status & params | Self-learning status and active PID parameters ($Kp, Ki, Kd$). |
| `sensor.multizone_brain_living_velocita_riscaldamento`| Sensor (Diagnostic) | °C/hour | Warm-up rate $R$ under full heating. |
| `sensor.multizone_brain_living_velocita_raffrescamento`| Sensor (Diagnostic) | °C/hour | Natural cool-down / cooling rate $D$ / $R_{\text{cool}}$. |
| `sensor.multizone_brain_living_inerzia_termica` | Sensor (Diagnostic) | minutes | Estimated thermal inertia for Smart Return lead times. |
| `sensor.multizone_brain_living_classe_energetica` | Sensor (Diagnostic) | A4, A, B, C, D, E, F, G | Estimated building energy class. |
| `sensor.multizone_brain_living_tempo_ritenzione_termica` | Sensor (Diagnostic) | hours | Thermal retention duration (hours to lose 1.0 °C). |
| `sensor.multizone_brain_living_dimensionamento_radiatore`| Sensor (Diagnostic) | Undersized, Optimal, Oversized | Radiator power sizing adequacy estimate. |
| `binary_sensor.heating_zones_living_anomaly` | Binary Sensor (Diagnostic) | `on` / `off` | Local anomaly flag (stuck valve, ghost heat, or sensor timeout). |

## 3. Exposed Home Assistant Services

### `multizone_thermostat.set_master_operation_mode`
<span class="badge-beta">BETA</span>

Switches whole-house operation between Heating and Cooling:

```yaml
service: multizone_thermostat.set_master_operation_mode
data:
  operation_mode: cool # 'heat' or 'cool'
```

---

### `multizone_thermostat.set_smart_return`
Schedules an intelligent arrival time with staggered preheating based on thermal inertia:

```yaml
service: multizone_thermostat.set_smart_return
data:
  arrival_time: "18:30" # "HH:MM" or ISO datetime
  preset: comfort
  zones:
    - climate.multizone_thermostat_living
    - climate.multizone_thermostat_bedroom
```

---

### `multizone_thermostat.cancel_smart_return`
Cancels any active Smart Return schedule:

```yaml
service: multizone_thermostat.cancel_smart_return
```

---

### `multizone_thermostat.activate_schedule_profile`
Activates a weekly schedule profile with optional auto-revert timeout:

```yaml
service: multizone_thermostat.activate_schedule_profile
data:
  profile_id: smart_working
  expires_at: "2026-11-15T19:00:00"
  fallback_profile: standard
```

---

### `multizone_thermostat.clear_zone_override`
Clears temporary manual setpoint overrides, restoring scheduled presets:

```yaml
service: multizone_thermostat.clear_zone_override
data:
  entity_id: climate.multizone_thermostat_living
```

---

### `multizone_thermostat.set_preset_temperature`
Updates target setpoint for a specific preset in memory:

```yaml
service: multizone_thermostat.set_preset_temperature
data:
  entity_id: climate.multizone_thermostat_bedroom
  preset: comfort
  temperature: 20.5
```

---

### `multizone_thermostat.set_pid_parameters`
Overrides seasonal PID gains (`kp`, `ki`, `kd`) for one or more zones, optionally targeting `heat` or `cool`, or seeding the Auto EMA baseline (`seed_autotuner`):

```yaml
service: multizone_thermostat.set_pid_parameters
data:
  entity_id:
    - climate.multizone_thermostat_living
  mode: heat          # Optional: 'heat' or 'cool' (defaults to active season)
  seed_autotuner: false # Optional: true to apply as learned Auto EMA baseline
  kp: 12.0
  ki: 0.015
  kd: 120.0
```

---

### `multizone_thermostat.reset_autotune`
Resets the passive autotuner for one or more zones on the selected seasonal track (saving a pre-reset backup) and relocks `PID Manual Unlock`:

```yaml
service: multizone_thermostat.reset_autotune
data:
  entity_id:
    - climate.multizone_thermostat_living
  mode: heat   # Optional: 'heat' or 'cool'
```

---

### `multizone_thermostat.restore_autotune`
Restores the learned Smart PID parameters and cycles saved before the last autotuner reset:

```yaml
service: multizone_thermostat.restore_autotune
data:
  climate_entity: climate.multizone_thermostat_living
  keep_manual_overrides: false # Optional: retain manual overrides after restoring backup
  mode: heat                   # Optional: 'heat' or 'cool'
```

---

### `multizone_thermostat.duplicate_schedule_profile`
Duplicates an existing weekly schedule profile under a new ID and name:

```yaml
service: multizone_thermostat.duplicate_schedule_profile
data:
  source_profile_id: standard
  target_profile_id: smart_working
  target_name: "Smart Working"
```
