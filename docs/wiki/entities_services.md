# Entities Created & Exposed Services

A complete reference of all entities automatically generated by **Multizone Thermostat** and services available for scripts and automations.

---

## 1. Master Plant Entities (Whole-House Supervision)

| Entity ID (Example) | Domain | State / Range | Description |
|---|---|---|---|
| `switch.master_control_heating_master` | Switch | `on` / `off` | **Master Plant Switch**: Powers ON or OFF climate control for the entire home. |
| `switch.master_control_weekly_scheduler` | Switch | `on` / `off` | Enables or pauses the built-in Weekly Matrix Scheduler. |
| `switch.master_control_allow_split_heating` | Switch | `on` / `off` | <span class="badge-beta">BETA</span> Global toggle to permit or lock Split AC heating. |
| `switch.master_control_allow_split_cooling` | Switch | `on` / `off` | <span class="badge-beta">BETA</span> Global toggle to permit or lock Split AC cooling. |
| `switch.master_control_anti_seize_summer_protection` | Switch | `on` / `off` | Enables summer anti-seize valve exercise. |
| `switch.master_control_anti_frost_protection` | Switch | `on` / `off` | Emergency frost protection toggle. |
| `switch.time_geofencing_geofencing` | Switch | `on` / `off` | Automated transition to Away preset on departure. |
| `switch.time_geofencing_auto_night_mode` | Switch | `on` / `off` | Automated clock-based transition to Sleep preset. |
| `time.time_geofencing_night_time` | Time | `HH:MM` (default: `22:30`) | Time at which Auto Night Mode activates the Sleep preset. |
| `time.time_geofencing_morning_time` | Time | `HH:MM` (default: `07:00`) | Morning recovery time exiting Auto Night Mode. |
| `select.master_control_heat_source_priority` | Select | `auto`, `hybrid`, `combined`, `electric_only`, `gas_only`, `gas_priority`, `electric_priority` | <span class="badge-beta">BETA</span> Arbitrates between gas boiler and heat pump / splits (7 priority modes). |
| `select.master_control_master_operation_mode` | Select | `heat`, `cool` | <span class="badge-beta">BETA</span> Master seasonal switch between Heating and Cooling. |
| `select.master_control_global_preset` | Select | `manual`, `eco`, `comfort`, `sleep`, `away` | Global household temperature preset selector. |
| `select.master_control_demand_strategy` | Select | `max`, `weighted_average`, `sum_capped` | Aggregation formula for central heating plant demand. |
| `select.master_control_schedule_profile` | Select | Profile IDs | Active weekly scheduler profile (`Standard`, `Smart Working`, `Holiday`, or custom). |
| `number.master_control_min_cycle_on` | Number | `0–60` min (default: `5`) | Minimum continuous burner run time. |
| `number.master_control_min_cycle_off` | Number | `0–60` min (default: `5`) | Minimum rest period before burner restart. |
| `number.master_control_heat_pump_min_cycle_on` | Number | `0–30` min (default: `5`) | <span class="badge-beta">BETA</span> Independent minimum continuous Heat Pump compressor run time. |
| `number.master_control_heat_pump_min_cycle_off` | Number | `0–30` min (default: `5`) | <span class="badge-beta">BETA</span> Independent minimum Heat Pump compressor rest period. |
| `number.master_control_valve_delay` | Number | `0–300` sec (default: `0`) | Pump delay to wait for motorized valve stroke (runs after the automatic up to 120 s `HOLD_TRV_CLOSED` TRV readiness guard). |
| `number.master_control_anti_seize_idle_days` | Number | `1–30` days (default: `15`) | Inactivity days before running anti-seize stroke. |
| `number.master_control_anti_seize_duration` | Number | `1–15` min (default: `2`) | Duration of valve opening during anti-seize. |
| `number.master_control_weather_curve` | Number | `0.0–3.0` (default: `1.0`) | Outdoor weather compensation curve multiplier (`0.0` disables feed-forward). |
| `number.master_control_anti_frost_temperature` | Number | `5.0–16.0 °C` (default: **`12.0`**) | Emergency freeze protection threshold. |
| `number.master_control_frost_protection_flow_temp` | Number | `25.0–55.0 °C` (default: `40.0`) | Configurable flow temperature during emergency frost protection (modulating/HP plants). |
| `sensor.master_control_master_demand` | Sensor | `0.0–100.0%` | Aggregated central plant demand (active in both `heat` and `cool`). |
| `sensor.master_control_plant_health_status` | Sensor | `Optimal`, `Warning`, `Critical` | Overall heating plant health status badge & reason attributes. |
| `sensor.master_control_boiler_cycles_per_hour` | Sensor | cycles/h | Boiler/plant hourly ignition cycle frequency (short-cycle alert `> 5 c/h`). |
| `sensor.master_control_boiler_daily_runtime_24h` | Sensor | hours | Cumulative boiler/plant runtime over the last 24h. |
| `binary_sensor.master_control_plant_anomaly` | Binary Sensor | `on` / `off` | Active when hydraulic or telemetry anomalies exist. |

## 2. Per-Zone Entities (Individual Rooms)

All per-zone entities (except `climate.*`) are grouped under each room's dedicated Home Assistant device (`Zona <Name>`, resulting in `zona_<name>_*` entity IDs) and organized into **Controls**, **Configuration**, and **Diagnostics** categories:

| Entity ID (Example for "Living") | Domain / Category | State / Values | Description |
|---|---|---|---|
| `climate.multizone_thermostat_living` | Climate (Control) | hvac_modes, setpoint, presets | **Primary Room Climate**: Sets target (configurable `target_temp_step`: `0.5°` or `0.1°`), HVAC mode, presets, and exposes TRV/PID attributes (`trv_calibration_mode`, `trv_sensor_selects`, `trv_control_mode`, `trv_open_boost`, `trv_close_offset`, `trv_demand_valve_open`, `pid_kp`, `pid_ki`, `pid_kd`, `active_heating_source`, `safety_fallback_active`, `local_pwm_active`). |
| `select.zona_living_mode` | Select (Control) | `primary`, `secondary`, `bypass` | **Room Thermal Role**: Determines if room can ignite central boiler. |
| `switch.zona_living_pid_manual_unlock` | Switch (Config) | `on` / `off` | Unlocks manual editing of seasonal PID gains (`Kp`, `Ki`, `Kd`). Defaults to locked. |
| `number.zona_living_pid_kp` / `ki` / `kd` | Number (Config) | `Kp: 0.1–500`, `Ki: 0.0–10.0`, `Kd: 0.0–50000` | Per-zone seasonal PID gains for the active season (`heat` or `cool`). |
| `button.zona_living_reset_autotuner` | Button (Config) | press | Resets the active season's autotuner (after saving a backup) and relocks `PID Manual Unlock`. |
| `switch.zona_living_physical_controls_sync` | Switch (Config) | `on` / `off` | Bidirectional synchronization for physical TRV dial turns. |
| `switch.zona_living_passive_heat` | Switch (Config) | `on` / `off` | Passive heat intake mode (suppresses false ghost-heating alerts in open spaces). |
| `sensor.zona_living_demand` | Sensor (Diagnostic) | `0.0–100.0%` | Real-time PID demand percentage. Exposes live attributes (`p_term`, `i_term`, `d_term`, `integral_accumulator`, `error`, `set_point`, `raw_output`, `clamped_output`, `kp`, `ki`, `kd`, `control_mode`, `weather_ff`, `smart_stop_offset`, `window_open`, `active_track`). |
| `sensor.zona_living_autotuning` | Sensor (Diagnostic) | status & params | SIMC self-learning status, active/learned PID parameters (`Kp`, `Ki`, `Kd`), and `weekly_guardrail_status` (`idle`, `monitoring`, `confirmed`, `reverted`). |
| `sensor.zona_living_heating_rate` | Sensor (Diagnostic) | `°C/hr` (`°F/hr`) | Warm-up rate $R$ under full heating. |
| `sensor.zona_living_cooling_rate` | Sensor (Diagnostic) | `°C/hr` (`°F/hr`) | Natural cool-down / active cooling rate $D$ / $R_{\text{cool}}$. |
| `sensor.zona_living_thermal_inertia` | Sensor (Diagnostic) | **`°C` (`°F`)** | Estimated post-shutdown thermal inertia temperature overshoot delta. |
| `sensor.zona_living_energy_class` | Sensor (Diagnostic) | `A4, A, B, C, D, E, F, G` | Estimated building energy class (derived primarily from weather-invariant Newton `k_loss`, with draft filtering & startup self-healing). |
| `sensor.zona_living_thermal_retention_time` | Sensor (Diagnostic) | hours (`h`) | Thermal retention duration (hours to lose `1.0 °C`). |
| `sensor.zona_living_radiator_sizing` | Sensor (Diagnostic) | `Undersized`, `Optimal`, `Oversized` | Radiator power sizing adequacy estimate. |
| `binary_sensor.zona_living_anomaly` | Binary Sensor (Diagnostic) | `on` / `off` | Local anomaly flag (`stuck_closed`, `trv_not_opening`, `ghost_heating`, `overshoot`, `stale_sensor`, `sensor_fault`). |

## 3. Exposed Home Assistant Services

### `multizone_thermostat.set_master_operation_mode`
<span class="badge-beta">BETA</span>

Switches whole-house operation between Heating and Cooling:

```yaml
service: multizone_thermostat.set_master_operation_mode
data:
  operation_mode: cool # 'heat' or 'cool'
```

---

### `multizone_thermostat.set_smart_return`
Schedules an intelligent arrival time with staggered preheating based on thermal inertia:

```yaml
service: multizone_thermostat.set_smart_return
data:
  arrival_time: "18:30" # "HH:MM" or ISO datetime
  preset: comfort
  zones:
    - climate.multizone_thermostat_living
    - climate.multizone_thermostat_bedroom
```

---

### `multizone_thermostat.cancel_smart_return`
Cancels any active Smart Return schedule:

```yaml
service: multizone_thermostat.cancel_smart_return
```

---

### `multizone_thermostat.activate_schedule_profile`
Activates a weekly schedule profile with optional auto-revert timeout:

```yaml
service: multizone_thermostat.activate_schedule_profile
data:
  profile_id: smart_working
  expires_at: "2026-11-15T19:00:00"
  fallback_profile: standard
```

---

### `multizone_thermostat.save_schedule_profile`
Creates or updates a weekly schedule profile programmatically:

```yaml
service: multizone_thermostat.save_schedule_profile
data:
  profile_id: standard
  name: "Standard Schedule"
  baseline_preset: eco
  days:
    mon:
      climate.multizone_thermostat_living:
        - start: "06:30"
          end: "08:30"
          preset: comfort
        - start: "17:00"
          end: "22:30"
          preset: comfort
```

---

### `multizone_thermostat.clear_zone_override`
Clears temporary manual setpoint overrides, restoring scheduled presets:

```yaml
service: multizone_thermostat.clear_zone_override
data:
  entity_id: climate.multizone_thermostat_living
```

---

### `multizone_thermostat.set_preset_temperature`
Updates target setpoint (`5.0–95.0`) for a specific preset in memory (`manual`, `comfort`, `eco`, `sleep`, `away`), optionally targeting `heat` or `cool`:

```yaml
service: multizone_thermostat.set_preset_temperature
data:
  entity_id: climate.multizone_thermostat_bedroom
  preset: comfort
  temperature: 20.5
  hvac_mode: heat # Optional: 'heat' or 'cool'
```

---

### `multizone_thermostat.set_pid_parameters`
Overrides seasonal PID gains (`kp`: `0.1–500.0`, `ki`: `0.0–10.0`, `kd`: `0.0–50000.0`), locks/unlocks manual editing (`lock_parameter` in `Kp`/`Ki`/`Kd`/`all`, `unlock`), or seeds the Auto EMA baseline (`seed_autotuner`):

> **PID Scaling Note:** Gains operate on `0–100%` demand output with `dt` in seconds (e.g., `kp: 100.0` outputs `100%` demand per `1 °C` error). Set `kd: 0.0` with `seed_autotuner: true` for pure PI control — weekly EMA refinement preserves `Kd = 0.0`.

```yaml
service: multizone_thermostat.set_pid_parameters
data:
  climate_entity: climate.multizone_thermostat_living # Also accepts legacy entity_id list
  mode: heat            # Optional: 'heat' or 'cool' (defaults to active/heat track)
  seed_autotuner: false # Optional: true to apply as learned Auto EMA baseline
  unlock: true          # Optional: explicitly unlock/lock manual editing
  lock_parameter: all   # Optional: restore 'Kp', 'Ki', 'Kd', or 'all' to autotuner baseline
  kp: 35.0
  ki: 0.015
  kd: 150.0
```

---

### `multizone_thermostat.reset_autotune`
Resets the passive autotuner for one or more zones on the selected seasonal track (saving a pre-reset backup) and relocks `PID Manual Unlock` unless `keep_manual_overrides: true`:

```yaml
service: multizone_thermostat.reset_autotune
data:
  climate_entity: climate.multizone_thermostat_living # Also accepts legacy entity_id list
  keep_manual_overrides: false # Optional: retain existing manual PID overrides
  mode: heat                   # Optional: 'heat' or 'cool'
```

---

### `multizone_thermostat.restore_autotune`
Restores the learned Smart PID parameters and cycles saved before the last autotuner reset:

```yaml
service: multizone_thermostat.restore_autotune
data:
  climate_entity: climate.multizone_thermostat_living
  keep_manual_overrides: false # Optional: retain manual overrides after restoring backup
  mode: heat                   # Optional: 'heat' or 'cool'
```

---

### `multizone_thermostat.duplicate_schedule_profile`
Duplicates an existing weekly schedule profile under a new ID and name:

```yaml
service: multizone_thermostat.duplicate_schedule_profile
data:
  source_profile_id: standard
  target_profile_id: smart_working
  target_name: "Smart Working"
```
